# 配置中心管理

## 概述

配置中心是微服务架构中的核心组件，用于集中管理所有服务的配置信息。它提供配置的动态更新、版本管理、环境隔离和安全访问控制，解决了传统配置文件的分散管理和硬编码问题。

## 核心功能

### 基本特性
```markdown
- **集中管理**: 所有配置集中存储和管理
- **动态更新**: 运行时配置热更新，无需重启服务
- **版本控制**: 配置变更历史和回滚能力
- **环境隔离**: 开发、测试、生产环境配置分离
- **权限控制**: 细粒度的配置访问权限管理
- **审计日志**: 所有配置变更的完整审计记录
```

## 主流配置中心方案

### 1. Spring Cloud Config

```yaml

          search-locations: classpath:/config

    active: git,native
```

### 配置优先级规则
```markdown
1. **命令行参数** (最高优先级)
2. **JVM系统属性**
3. **环境变量**
4. **配置文件** (application-{profile}.yml)
5. **默认配置** (application.yml)
```

### Apollo 动态配置
```java
@Component
public class DynamicConfig {
    
    @ApolloConfig
    private Config config;
    
    public String getConfigValue(String key) {
        return config.getProperty(key, null);
    }
    
    @ApolloConfigChangeListener
    public void onConfigChange(ConfigChangeEvent event) {
        for (String key : event.changedKeys()) {
            ConfigChange change = event.getChange(key);
            logger.info("Config changed - key: {}, oldValue: {}, newValue: {}", 
                key, change.getOldValue(), change.getNewValue());
        }
    }
}
```

## 安全与权限控制

### 配置加密
```yaml
# Jasypt加密配置
jasypt:
  encryptor:
    password: ${JASYPT_PASSWORD}  # 加密密钥
    algorithm: PBEWithMD5AndDES

# 加密配置值
datasource:
  password: ENC(加密后的密码)
```

```java
// 配置加密工具
public class ConfigEncryptor {
    
    public String encrypt(String value) {
        StandardPBEStringEncryptor encryptor = new StandardPBEStringEncryptor();
        encryptor.setPassword(System.getenv("JASYPT_PASSWORD"));
        return encryptor.encrypt(value);
    }
    
    public String decrypt(String encryptedValue) {
        StandardPBEStringEncryptor encryptor = new StandardPBEStringEncryptor();
        encryptor.setPassword(System.getenv("JASYPT_PASSWORD"));
        return encryptor.decrypt(encryptedValue);
    }
}
```

## 监控与审计

### 配置变更审计
```java
@Component
public class ConfigChangeAudit {
    
    @EventListener
    public void auditConfigChange(EnvironmentChangeEvent event) {
        Map<String, Object> auditData = new HashMap<>();
        auditData.put("timestamp", Instant.now());
        auditData.put("changes", event.getKeys());
        auditData.put("source", "config_server");
        
        auditLogger.info("Config changes detected: {}", auditData);
    }
}
```

## 灾备与恢复

### 配置备份策略
```bash
#!/bin/bash
# 配置备份脚本
BACKUP_DIR="/backup/config"
DATE=$(date +%Y%m%d_%H%M%S)

# 备份Git配置仓库
git clone https://github.com/example/config-repo $BACKUP_DIR/config-repo_$DATE

# 备份数据库配置
mysqldump -u root -p config_db > $BACKUP_DIR/config-db_$DATE.sql

# 上传到云存储
aws s3 sync $BACKUP_DIR s3://config-backup-bucket/
```

### 配置回滚机制
```java
@Service
public class ConfigRollbackService {
    
    public void rollbackConfig(String application, String version) {
        // 回滚到指定版本
        configServer.rollback(application, version);
        
        // 通知所有客户端刷新
        refreshAllClients(application);
    }
    
    private void refreshAllClients(String application) {
        // 通过消息队列通知客户端刷新配置
        kafkaTemplate.send("config-refresh", application);
    }
}
```

## 最佳实践

### 配置规范
```markdown
1. **命名规范**
   - 使用小写字母和连字符
   - 统一的前缀命名空间
   - 明确的配置项含义

2. **组织结构**
   - 按功能模块分组配置
   - 环境特定的配置分离
   - 公共配置提取共享

3. **安全要求**
   - 敏感配置加密存储
   - 最小权限原则
   - 定期审计配置访问
```

### 多配置源加载
```java
@Configuration
public class MultiConfigSource {
    
    @Bean
    @Order(0)
    public PropertySource<?> gitConfigSource() {
        // 从Git加载配置
        return new GitPropertySource();
    }
    
    @Bean
    @Order(1)
    public PropertySource<?> localConfigSource() {
        // 本地配置文件
        return new FileSystemPropertySource();
    }
    
    @Bean
    @Order(2)
    public PropertySource<?> defaultConfigSource() {
        // 默认配置
        return new MapPropertySource("defaults", getDefaultConfig());
    }
}
```

## 故障排查

### 常见问题解决
```markdown
1. **配置无法加载**
   - 检查配置中心连接
   - 验证配置文件路径
   - 查看客户端日志

2. **配置更新不生效**
   - 检查@RefreshScope配置
   - 验证配置监听器
   - 查看配置刷新端点

3. **配置冲突**
   - 检查配置优先级
   - 查看配置覆盖规则
   - 验证环境变量设置
```

## 总结

配置中心是现代微服务架构的关键组件，正确实施可以：

**核心价值：**
- 统一配置管理
- 动态配置更新
- 环境隔离管理
- 安全访问控制

**实施要点：**
- 选择合适的配置中心方案
- 制定配置管理规范
- 实施完善的监控审计
- 建立灾备恢复机制

> 提示：配置中心不是银弹，需要根据团队规模、技术栈和业务需求选择合适的解决方案。
