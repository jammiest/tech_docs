# 正则表达式断言与边界详解

> 断言和边界是正则表达式中用于匹配特定位置而非实际字符的强大工具，它们能够实现更精确的文本匹配和验证。

## 边界匹配（Boundary Matchers）

边界匹配用于指定匹配发生的位置，而不是匹配实际的字符。

### 常用边界匹配符

| 边界符 | 描述 | 示例 |
|--------|------|------|
| `^` | 匹配行的开头（多行模式下匹配每行开头） | `^abc` 匹配以 "abc" 开头的行 |
| `$` | 匹配行的结尾（多行模式下匹配每行结尾） | `abc$` 匹配以 "abc" 结尾的行 |
| `\b` | 匹配单词边界（单词与非单词字符之间） | `\bword\b` 匹配独立的单词 "word" |
| `\B` | 匹配非单词边界 | `\Bword\B` 匹配 "swordfish" 中的 "word" |
| `\A` | 匹配输入的开头（不受多行模式影响） | `\Aabc` |
| `\Z` | 匹配输入的结尾（不受多行模式影响） | `abc\Z` |
| `\z` | 匹配输入的绝对结尾 | `abc\z` |
| `\G` | 匹配上一次匹配的结束位置 | `\G\d` |

### 边界匹配示例

```regex
# 匹配独立的单词 "the"
\bthe\b

# 匹配行首的注释（如Python的 # 注释）
^#.*$

# 匹配文件扩展名（如 .txt）
\.\w+$

# 匹配C语言中的函数定义
^\w+\s+\w+\([^)]*\)\s*{$
```

## 断言（Assertions）

断言用于指定匹配必须满足的条件，但不消耗字符（即不成为匹配结果的一部分）。

### 零宽断言（Zero-width Assertions）

#### 1. 先行断言（Lookahead Assertions）

| 断言 | 描述 | 示例 |
|------|------|------|
| `(?=pattern)` | 正向先行断言 - 匹配后面跟着pattern的位置 | `\w+(?=;)` 匹配后面跟着分号的单词 |
| `(?!pattern)` | 负向先行断言 - 匹配后面不跟着pattern的位置 | `\d{3}(?!\d)` 匹配后面不跟着数字的3位数字 |

#### 2. 后行断言（Lookbehind Assertions）

| 断言 | 描述 | 示例 |
|------|------|------|
| `(?<=pattern)` | 正向后行断言 - 匹配前面是pattern的位置 | `(?<=\$)\d+` 匹配前面是美元符号的数字 |
| `(?<!pattern)` | 负向后行断言 - 匹配前面不是pattern的位置 | `(?<!-)\d+` 匹配前面不是连字符的数字 |

### 断言示例

```regex
# 匹配后面跟着px的数字（不包含px）
\d+(?=px)

# 匹配前面是$的数字（不包含$）
(?<=\$)\d+

# 匹配不在引号内的单词
\b\w+\b(?!")

# 匹配不在HTML标签内的内容
(?<=>)([^<]+)(?=<)

# 匹配强密码（至少8字符，包含大小写字母和数字）
^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$

# 匹配不连续的重复单词
\b(\w+)\b(?=.*\b\1\b)
```

## 边界与断言的高级应用

### 1. 提取特定上下文的内容

```regex
# 提取双引号内的内容（不包含引号）
(?<=")[^"]+(?=")

# 提取HTML标签内容（不包含标签）
(?<=<div>).*?(?=</div>)

# 提取Markdown链接的URL
\[.*?\]\((?<url>.*?)\)
```

### 2. 复杂验证

```regex
# 验证不包含连续空格的字符串
^(?!.*\s{2}).*$

# 验证不包含特定单词的字符串
^(?!.*\b(?:badword1|badword2)\b).*$

# 验证至少包含两种字符类型的密码
^(?=.*[a-z])(?=.*[A-Z0-9]).+$
```

### 3. 高级文本处理

```regex
# 在每行行首添加前缀（替换时使用）
^ --> Prefix

# 在每行行尾添加后缀（替换时使用）
$ --> Suffix

# 匹配不在括号内的逗号
,(?![^()]*\))
```

## 性能考虑

1. **后行断言限制**：某些正则引擎对后行断言有长度限制
   ```regex
   # 可能有问题（如果pattern太长）
   (?<=a{100})b
   ```

2. **避免复杂断言组合**：复杂的断言组合可能导致性能下降
   ```regex
   # 性能可能较差
   ^(?=.*a)(?=.*b)(?=.*c).*$
   ```

3. **具体化断言模式**：尽可能具体化断言中的模式
   ```regex
   # 不好
   (?<=.*a)b
   
   # 更好
   (?<=\w+a)b
   ```

## 跨语言支持

不同正则引擎对断言的支持程度不同：

| 特性 | PCRE | JavaScript | Python | Java | .NET |
|------|------|------------|--------|------|------|
| 先行断言 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 后行断言 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 后行固定长度 | ❌ | ❌ | ✅ | ✅ | ✅ |
| 后行变长 | ✅ | ✅ | ❌ | ❌ | ✅ |

## 实际案例

### 1. 提取CSS中的颜色值

```regex
# 匹配所有CSS颜色值（十六进制、rgb、rgba）
#(?:[a-fA-F0-9]{6}|[a-fA-F0-9]{3})\b|rgb\((?:\d{1,3},\s*){2}\d{1,3}\)|rgba\((?:\d{1,3},\s*){3}\d*\.?\d+\)
```

### 2. 验证复杂密码规则

```regex
# 密码要求：8-20字符，至少一个大写字母、一个小写字母、一个数字、一个特殊字符
^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[@$!%*?&])[A-Za-z\d@$!%*?&]{8,20}$
```

### 3. 匹配Markdown中的图片标签

```regex
# 匹配Markdown图片标签并提取描述和URL
!\[(?<description>[^\]]*)\]\((?<url>[^\)]+)\)
```

## 总结

断言和边界是正则表达式中极其有用的特性：

- **边界匹配**：用于精确控制匹配发生的位置（行首、行尾、单词边界等）
- **断言**：提供条件匹配能力而不消耗字符（先行、后行、正向、负向）
- **高级应用**：复杂验证、上下文提取、文本处理等
- **性能考虑**：合理使用断言，避免过度复杂的模式

> 提示：断言和边界虽然强大，但使用时应保持模式简洁明了。对于特别复杂的匹配需求，可能需要考虑结合其他文本处理技术或分步骤处理。
